# 전자책 원스톱 스튜디오

사용자의 주제와 브랜드를 하나의 편집 시스템으로 묶어, 읽을 수 있는 원고와 편집 가능한 전자책 파일을 만든다. 특정 저자, 브랜드, 판권 정보, 성과 보장, 전문 자격은 임의로 가정하지 않는다.

## 시작 입력

다음 항목을 받되, 빠진 항목은 합리적인 기본값으로 진행하고 결과에 가정을 적는다. 저자명·브랜드명·판권 정보처럼 출판물에 사실로 인쇄되는 정보만 불명확하면 확인한다.

- 주제, 독자, 독자가 겪는 문제, 책이 약속하는 변화
- 저자명/브랜드/출판사, 책의 목적(판매·리드자석·강의교재 등)
- 희망 분량 또는 장 수, 톤, 금지 표현과 반드시 포함할 내용
- 디자인 무드, 주조색, 이미지 스타일, 로고·참고 이미지 유무
- 판권 정보(발행일, 연락처, ISBN 등). 없으면 빈칸이나 `추후 입력`으로 두고 꾸며내지 않는다.

입력이 매우 짧으면 먼저 3개의 차별화된 제목·부제·핵심 콘셉트를 제안하고 가장 설득력 있는 안을 추천한다. 사용자가 즉시 제작을 요청했다면 추천안을 채택해 계속 진행한다.

## 제작 순서

1. `references/editorial-system.md`를 읽고 독자 변화, 차별점, 목차의 논리 흐름을 설계한다.
2. 제목·부제·판매 문구, 독자 정의, 책의 한 문장 약속, 목차와 장별 학습 결과를 확정한다.
3. 목차 승인 요청은 사용자가 중간 확인을 원할 때만 한다. 그렇지 않으면 전체 원고까지 진행한다.
4. 각 장은 개념 설명만 늘이지 말고 사례, 자기점검 질문, 실천법 중 최소 2개를 포함한다. 심리·건강·재무·법률 주장은 단정하지 말고, 최신성이나 정확성이 중요한 사실 주장은 확인 가능한 출처를 조사·인용한다.
5. 초고가 완성되면 `humanize-korean` 스킬을 적용해 AI 티가 나는 번역투, 기계적 병렬, 접속사 남발, 리듬 균일, 과한 불릿을 점검하고 문체·리듬·표현만 자연스럽게 윤문한다. 이때 사실·주장·수치·날짜·고유명사·인용문·판권 정보는 변경하지 않고, 원고의 장르와 격식은 유지한다. 변경률은 기본 10~25% 범위로 관리하며 30%를 넘으면 과윤문 여부를 재검토한다.
6. 윤문본을 장별로 다시 읽어 의미 보존, 사례의 자연스러움, 독자에게 말 거는 문장 리듬, 실천 안내의 구체성을 점검한다. 필요하면 장별 마무리 문장과 전환 문장만 추가로 다듬되 새로운 주장이나 근거 없는 성과 보장은 넣지 않는다.
7. `references/visual-system.md`를 읽어 표지, 판권 배경, 각 부/장 오프너 이미지를 하나의 아트디렉션으로 설계한다. 이미지는 원고 제목·부제·목차·본문·장 제목이 먼저 확정된 뒤 제작한다.
8. 이미지가 필요한 단계에서는 현재 Codex 환경에서 사용할 수 있는 이미지 생성/편집 기능이 있는지 먼저 확인한다. 가능하면 `openai-image-generator` 또는 현재 제공되는 이미지 생성/편집 도구를 반드시 우선 사용해 실제 이미지 파일을 만든다.
9. 표지, 판권 배경, 각 부/장 오프너 이미지는 단순 장식이 아니라 전자책 산출물의 일부다. 실제 이미지 생성 기능을 사용할 수 있다면 표지, 장별 오프너, 판권 배경을 직접 이미지로 생성한다.
10. 표지와 장/부 오프너 이미지는 A4 세로 한 페이지 비율로 제작하고, 확정된 제목·부제·장 번호·장 제목 텍스트를 이미지 안에 넣는다. 생성 도구가 한글을 틀리게 만들면 무문자 실제 이미지 위에 편집 도구로 정확한 한글 텍스트를 합성해 최종 이미지 파일로 저장한다. 판권 페이지 이미지는 배경만 제작하며, 판권 문구는 Word에서 편집 가능한 텍스트로 둔다.
11. SVG, 단순 도형, 기본 그라데이션, 아이콘 조합, 템플릿식 배경은 실제 이미지의 대체물이 아니다. 이미지 생성이 불가능한 경우에만 최종 이미지 프롬프트, 권장 비율, 파일명, 삽입 위치를 제공한다.
12. 이미지 생성이 불가능하더라도 저품질 플레이스홀더나 단순 도형을 최종 이미지처럼 DOCX에 삽입하지 않는다. 이미지가 미완료인 경우에는 DOCX 안에 잘못된 최종 이미지 대신 명확한 이미지 배치 메모와 매니페스트를 남긴다.
13. 작업 디렉터리에 `book.json`을 작성하고 `scripts/build_ebook.py` 또는 동등한 DOCX 조립 스크립트로 편집 가능한 DOCX를 만든다. 표지·장/부 오프너·판권 배경 이미지는 각 자리에 한 페이지 전체 이미지로 배치하고, 목차와 본문은 Word 텍스트로 편집 가능하게 배치한다.
14. 문서 렌더링 도구가 있으면 DOCX를 렌더링하고 모든 페이지를 육안 점검한다. 깨진 한글, 외톨이 제목, 빈 페이지, 이미지 찌그러짐, 표 잘림을 수정한 뒤 다시 렌더링한다.
15. `references/qa-checklist.md`의 원고·시각·판권·파일 점검을 통과한 뒤 납품한다.

## 산출물

- 편집 가능한 `.docx` 1개
- 표지 이미지 1개
- 판권 페이지 배경 이미지 1개
- 각 장 또는 각 부의 오프너 이미지(사용자가 원하는 단위)
- 이미지 파일명과 대응 장을 적은 간단한 매니페스트
- 원고 윤문 요약 1개(`humanize-korean` 적용 여부, 변경률 범위, 의미 보존 점검 결과)

요청 시 PDF를 추가하되 DOCX를 대체하지 않는다. 이미지가 많으면 폴더 구조를 유지한 ZIP도 함께 제공한다.

## 디자인 원칙

- 표지·판권·장 이미지는 색, 재질, 조명, 상징, 인물 표현을 공유해야 한다.
- 장 이미지는 장 내용을 문자 그대로 묘사하기보다 핵심 감정을 상징화한다.
- 이미지가 필요한 산출물에서는 anime-cardnews-studio처럼 이미지 생성/편집 기능을 실제 제작 도구로 우선 사용한다. 모델이 기억한다고 가정하지 말고 표지, 판권 배경, 장 오프너마다 공통 아트디렉션과 개별 장면 지시를 반복한다.
- SVG, 단순 도형, 기본 그라데이션, 아이콘 조합은 기획 도식이나 편집 보조 요소일 수는 있지만 표지·장 오프너·판권 배경 이미지의 최종 대체물로 쓰지 않는다.
- 가독성을 위해 본문 위에 복잡한 이미지를 깔지 않는다. 이미지는 표지/오프너/구분 페이지에 집중한다.
- Word의 제목, 목차, 본문, 인용, 실천 박스에는 실제 스타일을 적용해 사용자가 전체 서식을 한 번에 바꿀 수 있게 한다.
- 기본 판형은 사용자가 다르게 요청하지 않는 한 A4 세로로 한다. 표지·장 오프너 이미지는 한 페이지 전체를 채우고, 장 본문은 다음 페이지부터 시작한다. 판권 배경과 판권 내용은 책 맨 뒤에 배치한다.
- 기본 글자 기준은 본문 12pt, 줄간격 1.5, 큰 제목 22pt, 장 제목 18pt, 소제목 14pt다. 독자층이 50대 이상이면 본문 가독성을 우선해 12pt를 기본으로 한다. Word 기본 불릿 점이 과하게 보이지 않도록 제목, 체크리스트, 목록은 좌측 점·불릿·하이픈 없이 처리한다. 제목 앞에 점이 붙는 환경에서는 Word 기본 제목 스타일 대신 일반 문단에 글자 크기·굵기·색을 직접 적용한다.
- 장 제목은 새 페이지에서 시작하며 제목만 페이지 하단에 홀로 남지 않게 한다.
- 표지는 썸네일 크기에서도 상단 제목, 중심 상징, 하단 저자·출판사 영역이 구분되어야 한다.

## 원고 윤문 원칙

- `humanize-korean`은 최종 원고의 내용 추가·삭제 도구가 아니라 문체 정리 도구로만 쓴다.
- 사실·주장·수치·날짜·고유명사·인용문·판권 정보·전문 자격 표현은 원문을 유지한다.
- 각 장의 첫 문단, 사례 문단, 실천 안내 문단을 우선 점검해 독자가 실제 저자의 목소리를 듣는 느낌을 살린다.
- 문장을 모두 짧게 쪼개거나 지나치게 구어체로 바꾸지 않는다. 전자책 장르에 맞는 격식과 친근함의 균형을 유지한다.
- 윤문 뒤에는 장별로 "의미가 바뀐 문장 없음", "근거 없는 약속 추가 없음", "반복 접속사와 병렬 구조 완화"를 확인한다.

## 프리셋

- 범용 기본값은 `references/visual-system.md`의 `warm-editorial`이다.
- 백도화/루모라 작업에는 사용자가 요청한 경우에만 `baekdohwa-luxury` 또는 `lumora-healing`을 쓴다.
- 프리셋은 출발점일 뿐이며 첨부 레퍼런스와 사용자의 명시적 선택이 우선한다.

## 자동화 스크립트

```bash
python scripts/build_ebook.py book.json output.docx
```

입력 스키마는 `references/book-schema.md`, 바로 복사해 쓸 기본 입력은 `assets/book-template.json`을 사용한다. 디자인 출발점은 `assets/design-presets.json`에서 고른다. `assets/sample-book.json`은 스크립트 동작 확인용 예시다. 스크립트는 제목/판권/자동 목차 안내/장 오프너/본문/인용/체크리스트/실천 박스를 구성하고 선택한 이미지를 삽입한다. Word에서 목차 필드를 열고 업데이트하면 페이지 번호가 반영된다.

스크립트에는 `python-docx`가 필요하다. 사용 가능한 Python 런타임에 해당 패키지가 없으면 DOCX 생성을 중단하고, 완성된 `book.json`과 이미지 프롬프트/배치 매니페스트를 대신 제공하면서 의존성 미충족을 알린다.

## 중단 조건

- 저자·출판사·연락처·ISBN을 추측해야만 진행되는 경우 해당 필드는 비워 두고 사용자에게 알린다.
- 이미지 생성/편집 기능을 사용할 수 없으면 이미지 프롬프트와 배치 매니페스트를 제공하고, 이미지 생성이 미완료임을 명확히 표시한다. 이때 단순 도형이나 저품질 플레이스홀더를 최종 이미지처럼 삽입하지 않는다.
- 렌더링 도구가 없으면 구조 검사를 수행하고 시각 QA 미완료를 알린다.
